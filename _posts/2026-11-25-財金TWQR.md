## 前言

TWQR 是財金資訊公司推動的共通 QR Code 規格，同一張 QR Code 可以讓不同銀行、電子支付的 App 掃碼使用，支援購物支付、購物轉帳、P2P 轉帳、繳費、繳稅與提款等交易。

QR Code 掃出來的內容，其實是一段類似網址的字串。開發串接時，需要知道每一段、每個參數代表什麼，這篇把字串結構和常用的參數整理成速查表。

> [!NOTE]
> 目前找不到財金公司公開的完整欄位規格。本文的欄位說明整理自 PTT 網友在 2018 年觀察大量 QR Code 後推測的結果，原作者也表示不一定完全正確，規格之後也可能更新。實際串接請以發卡行或財金公司提供的文件為準，來源見文末「參考資料」。

## TWQR 字串結構

由商店出示、讓消費者用 App 掃描的「主掃模式」QR Code，內容格式如下：

```text
TWQRP://服務名稱/國家代碼/交易類別/V1?D1=值&D2=值
```

- **服務名稱**：由銀行或店家自訂，轉帳時填什麼都不影響交易；中文要經過 UTF-8 URL 編碼。
- **國家代碼**：ISO 3166-1 的三位數字代碼（不是英文的 `TWN`），臺灣是 `158`，可以參考[代碼清單](https://en.wikipedia.org/wiki/ISO_3166-1_numeric)。
- **交易類別**：見下方「交易類別」。
- **V1**：原文沒有說明，推測是格式版本。
- **交易參數**：接在 `?` 後面，寫成「參數=值」，多個參數用 `&` 串接，見下方「交易參數」。

反過來由消費者的 App 產生、讓商店掃描的「被掃模式」，是把資料用 TLV 格式編碼後再轉成 Base64，格式完全不同，本文不涵蓋。

### 交易類別

| 代碼 | 類別                         |
| ---- | ---------------------------- |
| 01   | 掃碼收付（金融卡 Smart Pay） |
| 02   | 轉帳                         |
| 03   | 繳費                         |

### 交易參數

參數名稱的字首代表類別：

- **D 類**：固定欄位，產生 QR Code 時就決定好，付款人不能修改。
- **M 類**：付款人掃描後可以自己修改，例如 `M1` 金額、`M9` 附言、`M14` 電子發票載具；從這些例子看，數字跟同號的 D 類參數對應。
- **E 類、O 類**：財金的介紹文章另外提到 E 類是個別加密保護的敏感欄位，O 類是保留給參加單位自訂的欄位，文章沒有列出細節。

以下是常用的 D 類參數：

| 參數 | 說明                         | 格式                                                                                                      |
| ---- | ---------------------------- | --------------------------------------------------------------------------------------------------------- |
| D1   | 金額                         | 最多 7 位整數，後面補 2 位小數，例如 100 元為 `10000`                                                     |
| D2   | 訂單編號                     |                                                                                                           |
| D3   | 交易驗證碼                   |                                                                                                           |
| D4   | 繳費期限（帳單上的期限）     | `YYYYMMDD`                                                                                                |
| D5   | 轉入銀行代碼                 | 3 位數                                                                                                    |
| D6   | 轉入銀行帳號                 | 16 位數，不足時前面補 0                                                                                   |
| D7   | 銷帳編號                     |                                                                                                           |
| D8   | 服務名稱（店家收單名稱）     |                                                                                                           |
| D9   | 附言                         |                                                                                                           |
| D10  | 交易幣別                     | ISO 4217 的三位數字代碼，未填時預設為 `901`（新臺幣），可以參考[代碼清單](https://en.wikipedia.org/wiki/ISO_4217) |
| D11  | 收單銀行及其註記             |                                                                                                           |
| D12  | QR Code 有效期限，超過就失效 | `YYYYMMDDHHMMSS`                                                                                          |
| D14  | 電子發票載具                 |                                                                                                           |
| D15  | 手續費                       | 跟 D1 一樣補 2 位小數；只顯示在交易確認頁，實際手續費仍依銀行標準收取                                     |
| D16  | 費用名稱                     |                                                                                                           |
| D20  | 備用欄位                     |                                                                                                           |
| D97  | QR Code 產生時間             |                                                                                                           |
| D98  | 用途不明                     |                                                                                                           |
| D99  | 推測是某種檢查碼             |                                                                                                           |

> [!TIP]
> D4 和 D12 容易搞混：D4 是帳單上的繳費日期，只到日；D12 是 QR Code 本身的有效期限，精確到秒，過了就不能再掃。

### 範例

一筆轉帳 100 元的字串大致長這樣（帳號為假資料）：

```text
TWQRP://%E7%AF%84%E4%BE%8B%E5%95%86%E5%BA%97/158/02/V1?D1=10000&D5=004&D6=0000001234567890&D10=901
```

- `%E7%AF%84%E4%BE%8B%E5%95%86%E5%BA%97`：服務名稱「範例商店」經過 UTF-8 URL 編碼後的結果
- `158`：臺灣
- `02`：轉帳
- `D1=10000`：金額 100 元
- `D5=004`、`D6=0000001234567890`：轉入的銀行代碼與帳號，帳號不足 16 位前面補 0
- `D10=901`：新臺幣
