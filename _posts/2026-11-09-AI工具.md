## 前言

近幾年 AI 快速普及，工作和生活中大大小小的事情，幾乎都能看到 AI 的影子，我們也越來越離不開它，學會使用 AI 已經是現代人的必備技能。

這篇整理我使用 AI 工具的筆記，目前先從 Claude Code 的設定結構開始。Claude Code 的設定檔種類很多，這裡整理每個檔案該放什麼，並附上範例。

## 一、Claude Code

### 結構介紹

個人設定放在 `C:\Users\{UserName}\.claude`，對這台電腦上的所有專案都有效。

| 路徑 | 用途 |
| :--- | :--- |
| `./CLAUDE.md` | 每次開新對話都會載入的個人指示 |
| `./config.json` | 非官方檔案，我自己用來存放 `CLAUDE.md` 提到的目錄白名單 |
| `./settings.json` | 權限規則（哪些操作直接允許、要詢問或禁止），也能設定 hooks、環境變數和預設模型 |
| `./skills/<名稱>/SKILL.md` | 可重複使用的工作流程，用 `/名稱` 呼叫，Claude 也會自動判斷使用 |
| `./commands/<名稱>.md` | skills 的舊寫法，用單一檔案建立 `/名稱` 指令 |
| `./agents/<名稱>.md` | 可以針對日常不同情境的工作流程設定子代理 |
| `./rules/<名稱>.md` | 寫給 Claude 的「開發規則」 |
| `./settings.json` 的 `hooks` | 特定事件發生時，自動執行指定動作 |

> [!WARNING]
> `CLAUDE.md` 是給 AI 的指示，不是強制限制。Claude 會把它當成背景資訊來參考，所以不保證每次都照做。一定要擋下的操作，請用 `settings.json` 的 `permissions` 或 hooks；但 Bash 的 deny 規則只比對指令文字，換個寫法可能擋不到，不算安全邊界。

### 1. `CLAUDE.md`

每次開新對話時，Claude Code 都會載入這個檔案，適合放你希望它一直遵守的規則，例如回覆語言、程式碼風格。

內容範例：

```markdown
## General

所有回覆的內容一律使用繁體中文顯示。

## 檔案存取白名單

- 任何檔案、目錄存取（讀取、寫入、建立、刪除）前，須先確認路徑是否位於 `C:\Users\{UserName}\.claude\config.json` 的 `allowedWriteDirectories` 白名單內。
- 白名單的結尾，如果是 `\\`，表示除了那層以外，子目錄以及更下層的目錄，皆在白名單範圍內；若沒有 `\\` 結尾，表示只有那層目錄在白名單。
- 路徑不在以上白名單內，必須先問過我並取得同意後，才可以存取。

## 撰寫程式碼時

- **程式碼風格**：直接生成符合現有專案風格的程式碼。
- **命名空間**：自動補齊缺少的 using 陳述式、自動刪除未使用的 using 陳述式。
- **變數命名**：優先使用 `var` 宣告變數，除非型別不明確。
```

### 2. 非官方的 `config.json`

用來存放與 `CLAUDE.md` 內容有關的資料，比方說存取目錄的白名單。Claude Code 本身不會讀這個檔案，是 `CLAUDE.md` 裡的規則要求 AI 去查它。

內容範例：

```json
{
  "allowedWriteDirectories": [
    "C:\\Users\\{UserName}\\Projects\\",
    "C:\\Users\\{UserName}\\Notes"
  ]
}
```

第一筆結尾有 `\\`，代表 `Projects` 底下的子目錄都包含在內；第二筆沒有，代表只有 `Notes` 這一層。

### 3. settings.json

設定允許、拒絕的指令，以及 hooks 參數、AI 預設模型等等。

內容範例：

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "attribution": {
    "commit": "",
    "pr": ""
  },
  "permissions": {
    "allow": [
      "Bash(git status *)"
    ],
    "deny": [
      "Bash(git push *)",
      "Bash(git branch -D *)"
    ]
  },
  "model": "opus",
  "extraKnownMarketplaces": {
    "claude-plugins-official": {
      "source": {
        "source": "github",
        "repo": "anthropics/claude-plugins-official"
      }
    }
  },
  "agentPushNotifEnabled": true,
  "modelSettings": {
    "claude-opus-5-5": {
      "effortLevel": "high"
    }
  }
}
```

| 欄位 | 說明 |
| :--- | :--- |
| `$schema` | 讓編輯器提供自動完成與格式檢查 |
| `attribution` | 自訂 commit 和 PR 的署名，留空代表不加 |
| `permissions` | `allow` 是直接允許，`deny` 是禁止 |
| `model` | 預設模型，`opus` 是模型別名 |
| `extraKnownMarketplaces` | 額外登錄的外掛市集 |
| `agentPushNotifEnabled` | 允許 Claude 在判斷有需要時，推播通知到手機 |
| `modelSettings` | 依模型分別設定，例如推理強度 `effortLevel` |

### 4. skills

skills（技能）是可重複執行的工作流程，可以用 `/名稱` 呼叫，Claude 也會自動判斷是否使用。

內容範例（`skills/commit-message/SKILL.md`）：

```markdown
---
name: commit-message
description: 分析目前的異動，產生中文 commit message。
argument-hint: "[關聯單號，如 PROJ-1234]（可省略）"
---

## 目的

...

## 參數

呼叫格式：`/commit-message PROJ-1234`

...以下省略
```

### 5. commands

跟 skills 是同一套機制，`commands/<名稱>.md` 和 `skills/<名稱>/SKILL.md` 都會建立 `/名稱` 指令。commands 是舊的單檔寫法，既有檔案可以繼續用；新寫的建議用 skills，還能附帶其他檔案。

內容範例（`commands/explain-gitchange.md`）：

```markdown
---
description: 整理目前 git 異動的重點
argument-hint: "[檔案路徑]（可省略）"
---

用 `git diff` 查看 $ARGUMENTS 的異動（沒有指定路徑就看全部），然後整理出：

1. 這次改動主要改了什麼
2. 影響到哪些功能
3. 有沒有需要注意的風險
```

### 6. agents

可以依據不同任務，設定不同領域的 agents（子代理）。

當 Claude 遇到符合的任務或工作，它會自動把工作交給對應的 agent 來處理，這就像一個主管把任務分配給不同的組員。

內容範例（`agents/code-reviewer.md`）：

```markdown
---
name: code-reviewer
description: 檢查 C# 程式碼的品質與可維護性，使用者要求 code review 時使用
tools: Read, Grep, Glob
model: opus
---

你是一位資深 C# 後端工程師。

- 了解 .NET Framework、.NET Core、.NET 等開發框架的寫法。
- 擅長寫出高效率、易維護、容易理解的程式。

每次被呼叫時，請：

1. 先閱讀原程式碼與所有註解，通常註解會解釋那一段程式在做的事情
2. 理解註解背後真正想修正的問題或想完成的目的
3. 列出發現的問題，依嚴重程度排序，並說明原因與建議改法
4. 只提出建議，不直接修改程式
```

### 7. rules

寫給 Claude 的開發規則，主要說明應該怎麼寫程式、什麼事情不能做、要遵守哪些規範。

放在 `C:\Users\{UserName}\.claude\rules` 對所有專案有效；放在專案的 `.claude/rules` 則只對該專案有效。檔案開頭的 `paths` 代表只有處理符合路徑的檔案時才套用。

內容範例（專案的 `.claude/rules/api.md`）：

```markdown
---
paths:
  - "src/api/**/*.cs"
  - "app/api/**/*.cs"
---

# API 開發規範

## 路由命名

- 使用 RESTful 風格：`GET /users`、`POST /users`、`DELETE /users/:id`
- 版本號放在 URL：`/api/v1/users`

## 回應格式

所有 API 必須回傳統一格式：

- 成功：`{ success: true, data: {...} }`
- 失敗：`{ success: false, error: "錯誤訊息" }`
```

### 8. hooks

hooks（鉤子）是 Claude Code 的自動觸發機制，讓你在特定事件發生時，自動執行某些動作，不需要每次手動提醒 Claude。

hooks 寫在 `settings.json` 的 `hooks` 裡，Claude Code 不會自動掃描資料夾，腳本要由設定指定才會執行。

hooks 的事件類型很多，下面列的是最常用、最容易上手的一批：

| 事件 | 觸發時機 |
| :--- | :--- |
| PreToolUse | Claude 執行工具之前，可以阻擋這次操作 |
| PostToolUse | Claude 執行工具成功之後 |
| SubagentStart | Claude 啟動子代理時 |
| SubagentStop | Claude 結束子代理時 |
| Stop | Claude 完成回覆時 |
| SessionStart | 對話開始或恢復時 |
| Notification | Claude Code 發出通知時 |
| FileChanged | 被監看的檔案發生變化時 |

下面的設定會在 Claude 每次執行 Bash 指令之前，先跑指定的腳本。

內容範例（`settings.json`）：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "C:/Users/{UserName}/.claude/hooks/my-script.sh"
          }
        ]
      }
    ]
  }
}
```
